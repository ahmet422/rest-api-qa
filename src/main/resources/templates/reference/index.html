Overview

How this lab fits together: a browser and an API can both talk to the same Spring app and the same database—through two different “front doors” and two ways to sign in.

Use the section buttons at the top to open REST basics and This API when you go deeper. Below is the zoomed-out view for the classroom whiteboard or projector.

1. Request journey

Same database for the website and the REST API. A click in the browser follows the Web path; Postman or automated tests use the REST path. Both go through services and JPA to the DB, then the answer flows back (HTML to the browser, JSON to the client).

2. USER vs ADMIN

Everyone who is signed in can browse. Only ROLE_ADMIN gets create/update/delete in the UI and in the API. A USER who calls a write endpoint receives 403 Forbidden after authentication succeeds.

3. Two ways to authenticate

The website uses form login: the server stores a session and the browser stores a cookie (CSRF tokens protect forms). The REST API under /api is stateless: you obtain a JWT from POST /api/login and send it on every request. Roles exist in both worlds so USER and ADMIN behave consistently.
